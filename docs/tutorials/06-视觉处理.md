# 06 · 视觉处理教程(usb_cam + cv_bridge + OpenCV)

> 对应工作区:`ros1_advanced_ws`,子模块 `usb_cam`(ros-drivers/usb_cam,固定 tag `0.3.7`,ROS1 最终版)+ 本仓库自定义包 `vision_demo`。

视觉是机器人自动瞄准的基础。本教程打通 ROS 视觉的**完整数据链**:摄像头驱动 → 图像消息 → cv_bridge 转 OpenCV → 图像处理 → 结果发布。

## 学习目标

1. 理解 `sensor_msgs/Image` 与 OpenCV `Mat` 的互转(cv_bridge);
2. 掌握 `image_transport`(压缩传输、多订阅者);
3. 完成一个「红色物体检测 + 可视化发布」的完整节点;
4. 了解相机标定(camera_info)的作用。

## 前置依赖

```bash
cd <仓库根目录>
rosdep install --from-paths ros1_advanced_ws/src --ignore-src -r -y
cd ros1_advanced_ws && catkin build usb_cam vision_demo && source devel/setup.bash
```

> cv_bridge 使用 apt 的 `ros-noetic-cv-bridge`(避免源码编译与系统 OpenCV 冲突);OpenCV 为系统 `libopencv-dev`。

## 完整流程

### 1. 准备摄像头

```bash
ls /dev/video*            # 确认设备存在(笔记本自带或 USB 摄像头)
```

没有真实摄像头时用虚拟设备(先 `sudo modprobe v4l2loopback`),或直接跳到第 4 步用测试图像。

### 2. 启动 usb_cam 驱动

```bash
roslaunch usb_cam usb_cam-test.launch
# 或指定设备与分辨率
rosrun usb_cam usb_cam_node _video_device:=/dev/video0 _image_width:=640 _image_height:=480 _pixel_format:=mjpeg
```

- 发布 `/usb_cam/image_raw`(`sensor_msgs/Image`)与 `/usb_cam/camera_info`;
- 没有 camera_info 时许多下游节点会报错,可用假信息顶替:`rosrun camera_calibration_parsers ...`,或让 `image_proc` 关闭(见 FAQ)。

### 3. 查看图像

```bash
rqt_image_view          # GUI 查看
rostopic hz /usb_cam/image_raw   # 确认帧率
```

### 4. 运行视觉示例节点(本仓库 `vision_demo`)

```bash
# 红色物体检测:订阅 /usb_cam/image_raw,发布 /red_detector/result
rosrun vision_demo red_detector ~image:=/usb_cam/image_raw

# 没有摄像头时,用测试图像源节点配合(虚拟摄像头同理)
rosrun vision_demo test_image_pub
rosrun vision_demo red_detector ~image:=/test_image
```

Rviz 或 rqt_image_view 订阅 `/red_detector/result`,画面中红色区域会被框出,检测结果文字发布在 `/red_detector/detections`(`std_msgs/String`)。

> 节点话题都在私有命名空间 `/red_detector/` 下,所以 remap 要写成 `~image:=/usb_cam/image_raw`(`~` 表示相对节点名解析)。

## 代码导读(`vision_demo/src/red_detector.cpp`)

四步走,对应 ROS 视觉节点的标准骨架:

```cpp
// 1. 订阅图像(用 image_transport 获得压缩传输支持)
image_transport::ImageTransport it(nh);
image_transport::Subscriber sub = it.subscribe("/usb_cam/image_raw", 1, &imageCallback);

// 2. 回调:cv_bridge 转 Mat
void imageCallback(const sensor_msgs::ImageConstPtr& msg) {
  cv::Mat frame = cv_bridge::toCvShare(msg, "bgr8")->image;
  // ...
}
```

3. **HSV 颜色空间检测**(光照变化下比 RGB 稳定):

```cpp
cv::Mat hsv, mask;
cv::cvtColor(frame, hsv, cv::COLOR_BGR2HSV);
cv::inRange(hsv, cv::Scalar(0, 100, 100), cv::Scalar(10, 255, 255), mask);  // 红色 H≈0/180
// 形态学去噪 + findContours 取最大轮廓 + boundingRect
```

4. **发布结果**:带框图像再走 `cv_bridge::CvImage(...).toImageMsg()` 发回话题;目标中心像素坐标可选地发 `geometry_msgs/PointStamped`(配合相机内参与 TF 可换算 3D 方向——下一步练习)。

HSV 阈值是**动态调参的好素材**:把 6 个阈值注册成 dynamic_reconfigure 参数,用 `rqt_reconfigure` 拖着滑条调,立刻理解「调参器」的价值。

## 练习任务

1. 给 red_detector 加 dynamic_reconfigure,HSV 阈值在线调;
2. 检测结果驱动底盘:目标在画面左侧 → 机器人左转(把像素误差映射成 `angular.z`,发布 `/cmd_vel`),实现「追红色物体」;
3. 换成 `cv::SimpleBlobDetector` 或 Hough 圆检测,对比鲁棒性;
4. 用 `rosbag record /usb_cam/image_raw` 录一段视频,离线调算法。

## 与舵轮项目的关联

- 自动瞄准的视觉链路与本教程同构:相机驱动 → cv_bridge → OpenCV 检测 → 结果发给控制节点;
- `camera_info` + TF(相机外参)是把 2D 像素换算成 3D 方向的桥梁,学习 [tf2 教程](01-tf2坐标变换.md)后可以打通「看到 → 指向」的完整链条;
- 图像帧率与处理耗时直接决定控制闭环频率,注意 `rqt_plot` 观察处理耗时话题(节点里已发布)。
