# 07 · 从 ros_control 底盘到导航与定位

本课使用进阶工作区里的 [control_lab](../../ros1_advanced_ws/src/control_lab/README.md) 和 [navigation_lab](../../ros1_advanced_ws/src/navigation_lab/README.md)，在同一台有 URDF、轮式里程计、激光雷达和 IMU 的机器人上连接完整链路。

## 先分清四个任务

| 任务 | 输入 | 输出 | 本仓库入口 |
| --- | --- | --- | --- |
| 里程计融合 | 轮速里程计、IMU 角速度 | 平滑的局部运动估计 | EKF / localization.launch |
| SLAM 建图 | 激光、里程计 TF | 地图与相对地图的位置 | gmapping / slam.launch |
| 已知地图定位 | 已保存地图、激光、里程计 | 地图中的位置估计 | AMCL / navigation.launch |
| 导航 | 地图、定位、传感器、目标位姿 | 发给底盘的速度指令 | move_base / navigation.launch |

EKF 提供连续的局部里程计，AMCL 在已有地图上定位，map_server 发布地图数据，建图由 SLAM 节点完成。move_base 使用定位结果规划运动，并通过底盘控制接口执行。

## 入手顺序

1. 按 [control_lab 指南](../../ros1_advanced_ws/src/control_lab/README.md)运行单关节 PID，确认目标、反馈和输出力矩。
2. 运行移动底盘 URDF，观察轮速、里程计、/scan 和 /imu/data。
3. 按 [navigation_lab 指南](../../ros1_advanced_ws/src/navigation_lab/README.md)运行 EKF，对照原始与融合后的里程计。
4. 使用附带的教学地图练习 AMCL 和目标导航，先验证导航链路。
5. 启动 gmapping、遥控建图、保存自己的地图，再切回 AMCL 导航。

随包附带的地图由教学场景几何生成，属于已知地图练习材料；自己完成 SLAM 实验时应另存真实建图结果，不把该材料当作已经完成建图的证据。

## 环境与构建

以下从仓库根目录开始，Ubuntu 20.04 + Noetic；只 source 进阶工作区。新增两个包使用系统 ROS 依赖，不要求下载大型第三方源码。

```bash
source /opt/ros/noetic/setup.bash
rosdep update --include-eol-distros --rosdistro noetic
rosdep install --from-paths ros1_advanced_ws/src/control_lab ros1_advanced_ws/src/navigation_lab --ignore-src --rosdistro noetic -y
bash scripts/build_learning.sh projects
source ros1_advanced_ws/devel/setup.bash
```

首次安装 rosdep、初始化与 apt 依赖步骤见 [navigation_lab 指南](../../ros1_advanced_ws/src/navigation_lab/README.md)。Noetic 已结束支持，更新 rosdep 缓存时需要显式包含该发行版。

每个新终端都在仓库根目录执行：

```bash
source /opt/ros/noetic/setup.bash
source ros1_advanced_ws/devel/setup.bash
```

完整启动参数、地图路径、遥控命令与目标客户端用法，以 [navigation_lab 的入手指南](../../ros1_advanced_ws/src/navigation_lab/README.md)为准。不同实验的 launch 各自包含仿真入口，切换实验时先 Ctrl+C 结束上一组，不叠加启动多个 Gazebo。

## TF 与数据所有权

```text
map
 └── odom                   AMCL 或 gmapping，二选一
      └── base_footprint    EKF 或底盘控制器，二选一
           └── base_link
                ├── laser
                └── imu_link
```

机器人内部固定/关节变换由 robot_state_publisher 根据 URDF 与 joint_states 发布。开启 EKF 时关闭 diff_drive_controller 的 odom TF，原始里程计消息仍保留；关闭 EKF 时恢复控制器的 odom TF，并让导航使用原始里程计。

| 数据 | 本项目名称 | 用途 |
| --- | --- | --- |
| 原始里程计 | /diff_drive_controller/odom | 轮式估计、EKF 输入 |
| 融合里程计 | /odometry/filtered | EKF 输出 |
| 激光 | /scan | 建图、AMCL、代价地图 |
| IMU | /imu/data | EKF 的角速度观测 |
| 底盘指令 | /diff_drive_controller/cmd_vel | 导航或遥控的 Twist 输出 |
| 导航任务 | /move_base | 带状态与结果的 Action |

一次实验只让导航器或遥控器中的一个发送底盘指令；相同话题有两个发布者会导致命令交替覆盖。

## 如何判断成功

- **控制**：controller_manager 中的控制器为 running，改变指令后关节反馈变化；停发速度后超时制动。
- **局部定位**：原始里程计、IMU 与融合输出时间戳持续更新；odom 到 base_footprint 只有一个发布者。
- **地图定位**：机器人运动后，激光与地图障碍对齐，AMCL 位姿持续更新；初始位置差较大时用 RViz 的 2D Pose Estimate。
- **导航**：依次观察目标接收、路径生成和运动执行，以 Action 返回 SUCCEEDED、最终位姿进入配置容差为完成标志。
- **建图**：地图随探索更新；保存的 YAML/PGM 能再次被 map_server 加载，AMCL 能在其中定位。

## 排错顺序

1. 模型是否生成、控制器是否 running；物理仿真是否暂停。
2. /clock 是否前进，节点是否使用仿真时间。
3. /scan、IMU、里程计的 frame_id、时间戳、频率是否正确。
4. TF 树是否连通、是否有人重复发布同一条边。
5. AMCL 初值和保存地图是否与当前世界匹配。
6. costmap 的 footprint、膨胀半径、障碍源与清除范围是否合理。
7. 最后再调局部规划器速度、加速度和轨迹评分。

## 扩展实验

- 同一路线分别记录 use_ekf=true/false 的里程计，比较平滑程度与轨迹误差，并记录仿真传感器的噪声设置。真实定位精度通过对应硬件实验评价。
- 换一份自己构建的地图，观察 AMCL 初值、地图分辨率与激光噪声的影响。
- 调整 footprint 或 inflation_radius，对比窄通道是否可通行。
- 修改 URDF 轮径后同步更新控制器参数，再做定距离实验；另做一次故意不同步的对照，观察里程计尺度误差。
- 完成后阅读[开源项目入手指南](../projects/README.md)，把同样的检查方法用于 RRBot、Jackal、TurtleBot3 和 robot_localization。
