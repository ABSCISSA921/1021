# 06 · 仓库维护约定

## 内容边界

| 位置 | 放什么 | 构建范围 |
| --- | --- | --- |
| `docs/` | 通用知识、学习路线、实验模板 | 无 |
| `ros1_learning_ws/src/` | 通信基础和入门仿真 | 基础学习工作区 |
| `ros1_advanced_ws/src/` | 专题示例及依赖 | 进阶学习工作区 |
| `dx_final/` | 独立项目源码、需求和专用文档 | 仅在该项目内构建 |

学习包不依赖 `dx_final`，其 CI 和默认安装命令也不扫描该目录。项目说明留在项目自己的 README/docs；根 README 只保留入口。所有工作区直接扩展 `/opt/ros/noetic`。

## 新增课程

1. 确定一个可验收目标，例如“能够取消 Action”。
2. 用独立 ROS 包放实现，包含 `package.xml`、`CMakeLists.txt`、README，以及必要的 `scripts/` 或 `src/`、`launch/`、`config/`。
3. README 写明前置条件、终端起始目录、命令、真实接口、预期现象、排错和练习。
4. 在文档索引与学习路线中加入入口，不用空目录代替尚未实现的课程。
5. 声明编译、运行、测试依赖。Python 节点用 `catkin_install_python`；C++ 节点声明安装目标。

## 第三方依赖

- 保持现有子模块路径；新增依赖前判断是否可使用发行版包。
- 保留上游许可证、固定 gitlink、写明用途，不把构建产物复制进源码包。
- 初始化时指定所属工作区路径；普通学习操作不执行 `git submodule update --remote`。
- 升级依赖单独提交，记录原提交、新提交和验证结果。

## 文档与记录

使用标准 Markdown 和相对链接，公式用 `$...$` / `$$...$$`。命令每行一条或使用明确的 Bash 续行。`<仓库根目录>` 是需要替换的占位符；可复制示例优先从仓库根目录出发。

实验记录可在本地另建 `notes/`，使用[模板](templates/实验记录.md)。按需提交整理后的文字和小型配置；bag、原始数据、缓存和 IDE 状态留在本地。

## 验证

仓库根目录：

```bash
python3 scripts/check_repo.py
git diff --check
bash scripts/build_learning.sh basics
```

通信示例运行测试：

```bash
source ros1_learning_ws/devel/setup.bash
cd ros1_learning_ws
catkin run_tests ros_basics --no-deps
catkin_test_results build/ros_basics
```

结构检查只验证本仓库文件，不检查第三方文档和源码，只读取可用的包清单。检查本地链接目标文件是否存在，不验证外网链接和标题锚点；检查 XML 语法、包名重复、跨独立项目自有包的显式依赖。同名第三方包可能由系统安装，不据此认定工作区串用；运行行为仍需构建和 ROS 实验验证。

学习 CI 与独立项目 CI 分开触发；仓库文档结构检查由学习 CI 执行。修改控制器、仿真或第三方依赖时，还应做对应工作区的构建与运行验证。
