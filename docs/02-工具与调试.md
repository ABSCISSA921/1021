# 02 · 工具与调试

本章介绍 ROS 开发中最常用的调试工具,大部分已随 `ros-noetic-desktop-full` 安装。舵轮控制器这类「看不见的算法」全靠它们调。

## 1. 可视化全家桶:rqt

rqt 是插件式图形工具集,一条命令启动多个插件:

```bash
rqt                                  # 空窗口,从菜单添加插件
rqt_graph                            # 计算图:节点与话题关系,排查「谁没连上谁」
rqt_plot                             # 话题曲线:把 Float64 话题画成实时曲线
rqt_reconfigure                      # 动态调参面板:运行时修改 dynamic_reconfigure 参数
rqt_topic                            # 图形化 echo/pub
rqt_console rqt_logger_level         # 日志查看与日志级别控制
```

### rqt_plot 实战

调试舵轮控制器时,想看「目标轮速 vs 实际轮速」的跟踪效果:

```bash
rqt_plot /debug/lf_wheel/target/data /debug/lf_wheel/actual/data
```

- 输入话题名后按 `+` 添加曲线;
- 右击图例可改颜色/线宽;
- 曲线明显滞后或振荡 → 增大 P / 减小 I;曲线有稳态误差 → 增大 I;超调大 → 增大 D。

### rqt_reconfigure 实战

```bash
rosrun rqt_reconfigure rqt_reconfigure
```

在面板里选 `sentry_chassis_controller`,即可在线改 8 个 PID、轮距轴距、加速度限制等参数。**注意**:动态参数只存在参数服务器中,重启 launch 后会回到 YAML 里的默认值;调好后要把数值抄回 `config/chassis_params.yaml`。

## 2. PlotJuggler

比 rqt_plot 强大得多的时间序列工具:缩放、拖拽、多曲线布局、数据导出,调 PID 的最终武器。

```bash
rosrun plotjuggler plotjuggler
# 启动后选择流(如 /debug/lf_wheel/target)开始记录,暂停后分析
```

配合舵轮控制器 `gui:=true keyboard:=true tools:=true` 启动参数,可一键拉起全套调试工具。

## 3. rosbag:录制与回放

把运行数据录下来,离线反复分析,不依赖仿真环境。

```bash
# 录制:只录调试话题
rosbag record -O tuning.bag /debug/lf_wheel/target /debug/lf_wheel/actual /odom
# 录制:全量
rosbag record -a

# 回放(数据会重新发布到原话题)
rosbag play tuning.bag

# 查看信息
rosbag info tuning.bag
```

配合 PlotJuggler:直接 `File → Load Data` 打开 `.bag` 文件,无需回放。

## 4. 日志:ROS_INFO 与 rqt_console

```bash
# 改变某节点日志级别(debug/info/warn/error)
rosservice call /<node>/set_logger_level ros.<node> debug

# 在 launch 文件中设置节点输出
<node ... output="screen"/>        # 输出到终端
<node ... output="log"/>           # 输出到 ~/.ros/log/
```

排查习惯:每个回调入口打一条带数值的 `ROS_INFO`,配合 `rqt_console` 按级别过滤。舵轮控制器源码里大量使用 `ROS_INFO_THROTTLE(1.0, ...)`:限频打印,1 秒最多一次,不会刷屏——写高频回调时应该照做。

## 5. catkin_tools 常用命令

本仓库统一使用 catkin-tools,不要混用 `catkin_make`:

```bash
catkin init                            # 初始化工作区(一次)
catkin config --extend /opt/ros/noetic # 指定上层环境(一次)
catkin build                           # 构建全部
catkin build <pkg>                     # 只构建某包
catkin build --no-deps <pkg>           # 只构建某包,不管其依赖
catkin clean                           # 清理 build/ devel/ logs/
catkin list                            # 列出发现的包
catkin build --verbose                 # 查看完整编译命令,排查编译错误
```

> 修改了 launch/yaml/cfg 后**不需要**重新编译(它们不参与 C++ 编译);修改了 `.cpp`/`.h` 后需要 `catkin build`。`build/`、`devel/`、`logs/`、`.catkin_tools/` 已在本仓库 `.gitignore` 中。

## 6. IDE 与调试器

### VS Code

1. 安装 ROS 插件(ms-iot.vscode-ros);
2. 打开工作区目录,`.vscode/c_cpp_properties.json` 的 includePath 加 `/opt/ros/noetic/include/**` 与各工作区 `devel/include/**`;
3. 启动调试前先 `source /opt/ros/noetic/setup.bash && source devel/setup.bash`,再以该环境启动 `code`,否则找不到包。

### CLion(舵轮项目考核指定)

- 官方教程:[CLion ROS Setup](https://www.jetbrains.com/help/clion/ros-setup-tutorial.html)。
- 调 Gazebo 插件(如舵轮控制器)时,用 **Attach to process** 附加到 `gzserver` 进程打断点:[Attaching to local process](https://www.jetbrains.com/help/clion/attaching-to-local-process.html)。

### 命令行 GDB

```bash
rosrun --prefix 'gdb -ex run --args' sentry_chassis_controller keyboard_teleop
# 或者 attach 到正在运行的进程
sudo gdb -p <pid>
```

## 7. Gazebo 调试技巧

```bash
# 无 GUI 跑(服务器/CI),gzclient 单独起
roslaunch diffbot_sim diffbot_gazebo.launch gui:=false
gzclient

# 查看世界里的模型与关节状态
gz model --info
gz topic -l
gz topic -e /gazebo/default/diffbot/joint_states
```

- `spawn_model` 报「模型没出现」:检查 `robot_description` 参数是否加载成功(`rosparam get /robot_description | head`)。
- 机器人抽搐/爆炸:优先怀疑 PID 过大、碰撞体互相穿透(URDF collision 几何错误)、控制器周期太慢。

## 8. 一键调试套件(舵轮)

```bash
roslaunch sentry_chassis_controller sentry_chassis_control.launch \
  gui:=true keyboard:=true tools:=true
```

`tools:=true` 会自动拉起 rqt_reconfigure、rqt_plot(目标/实际轮速)、RViz 和 PlotJuggler。键盘操作见 [sentry_chassis_controller README](../dx_final/src/sentry_chassis_controller/README.md)。
