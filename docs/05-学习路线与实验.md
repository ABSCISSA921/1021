# 05 · 学习路线与实验

按能力推进，不按天数赶进度。每个实验至少留下：运行命令、一份输出或 bag、对数据流的解释、一个失败案例。记录格式见[模板](templates/实验记录.md)。

## 阶段 1：建立 ROS 通信模型

入口：[ros_basics](../ros1_learning_ws/src/ros_basics/README.md)。只需 ROS 核心环境，不需要图形界面。

| 实验 | 动手内容 | 验收标准 |
| --- | --- | --- |
| L01 话题 | talker/listener、自定义消息 | 说出发布者、订阅者、类型和频率 |
| L02 参数与命名空间 | robot_a/robot_b、remap | 两组计数流互不串线，参数路径正确 |
| L03 服务 | 正数、负数、较大整数；停止服务端 | 结果正确，等待失败能说明原因 |
| L04 Action | 完成倒计时、主动取消、feedback | 区分 SUCCEEDED、PREEMPTED 与 ABORTED |
| L05 回放 | 录包，停止发布者，重新播放 | 解释为何原始时间戳没有变成当前时间 |

练习扩展：给 `Counter.msg` 增加 `float64 value`，发布正弦波并在 rqt_plot 中观察。修改接口后重新构建并重启通信两端；比较它与只改 YAML 的区别。

## 阶段 2：从 Python 过渡到 C++ 与仿真

先按[基础工作区](../ros1_learning_ws/README.md)安装仿真依赖。

1. 读 `ros_pkg/src/v_node.cpp`，画出订阅、回调、状态机和速度输出关系。列出坐标、距离和角度的单位。
2. 在提供 `/scan`、`/odom` 的 WPR 场景运行状态机，先用 `rostopic info` 核实接口。现有 DiffBot **没有激光雷达**，不能直接满足此实验。
3. 运行 TurtleBot3 多机跟随，记录两个机器人的命名空间与 TF frame；修改一个 frame 名，观察异常日志并修复。
4. 运行 DiffBot，沿 `/cmd_vel` → Gazebo 插件 → `/diffbot_controller/cmd_vel` 跟踪指令；比较命令与 `/diffbot_controller/odom` 反馈。

验收：能根据实际节点图和话题信息定位断点，而不是只凭“车动不动”判断程序。

## 阶段 4：学习综合实验

选一个方向，在学习工作区新增自己的包，不修改第三方子模块：

- **通信监测器**：订阅计数，报告频率与过大的消息间隔；通过服务查询统计值，通过参数配置阈值。停止发布者后应能观察到超时。
- **多机队列**：为跟随例子增加第三台机器人；每台机器人有独立名称、速度话题和 TF frame。记录 leader 停止后的行为。
- **离线视觉评估**：录制或生成图像，比较不同阈值的检测结果，报告漏检案例。不要把像素坐标直接当成三维位置。

提交内容：包 README、launch/config、接口表、复现步骤、实验记录。完成标准是其他人能按文档复现，并能解释一项成功证据和一项限制。
