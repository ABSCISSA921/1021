# 03 · 常见问题(FAQ)

按工作区分组的常见问题与排查思路。出现新问题时的通用排查顺序:**看日志 → 看 rqt_graph → 看参数 → 查 TF**。

## 通用

### 子模块目录是空的
克隆时忘了 `--recurse-submodules`。在仓库根目录执行:

```bash
git submodule sync --recursive
git submodule update --init --recursive
```

### 子模块处于 detached HEAD
正常现象。本仓库的子模块全部固定提交以保证可复现,**不要**把它们切回分支、也不要升级提交(除非有意为之)。

### `catkin build` 报找不到包 / 找不到头文件
1. 确认在**工作区根目录**(有 `src/` 的那层)执行 `catkin build`,不是在 `src` 里;
2. 确认已 `source /opt/ros/noetic/setup.bash` 且工作区执行过 `catkin config --extend /opt/ros/noetic`;
3. 确认子模块已初始化;
4. 换过路径/发行版后出现旧缓存:删除本机 `build/ devel/ logs/ .catkin_tools/`,重新 `catkin build`。

### `roslaunch` 提示 `[pkg] is not a package`
当前终端没有 source 对应工作区的环境:

```bash
source /opt/ros/noetic/setup.bash
source <workspace>/devel/setup.bash
```

把两条都写进 `~/.bashrc` 一劳永逸(注意先后顺序)。

### rosdep 报错
- `rosdep init` 提示已存在 → 跳过;
- `rosdep update` 网络超时 → 换镜像、挂代理或多试几次;
- `rosdep install` 个别 key 解析失败 → 记下包名,`apt search ros-noetic-<name>` 手动安装;或给命令加 `-r` 忽略后逐个补。

### Gazebo 打开是黑屏 / 闪退
1. 显卡驱动问题(虚拟机常见):`export LIBGL_ALWAYS_SOFTWARE=1` 再试;
2. 无显示器环境:用 `gui:=false` 无头运行;
3. 查看详细报错:`gazebo --verbose`。

### 仿真中时间错乱 / TF 报 extrapolation
仿真必须用模拟时钟。确认 launch 里设置了 `/use_sim_time=true`,且**不要**在仿真的终端里混用 `rosbag play` 的真实时间。

## ros1_learning_ws

### TurtleBot3 launch 找不到模型
必须先设置车型环境变量:

```bash
export TURTLEBOT3_MODEL=burger   # 可选 burger / waffle / waffle_pi
```

### `multi_turtlebot3.launch` 里机器人不动
- 焦点放在 teleop 终端,用键盘控制 `tb3_0`;`tb3_1`(跟随者)由 `follower_node` 自动控制;
- 确认 `follower_node` 输出没有持续 `TF查询异常`;有的话用 `rosrun tf2_tools view_frames.py` 检查 TF 树。

### diffbot 云台不转
云台跟随逻辑在 Gazebo 插件 `chassis_follower_plugin` 里。用 `rostopic echo /turret_controller/command` 看有没有指令;没有则检查 `/cmd_vel` 是否有发布者(`rostopic info /cmd_vel`)。

## dx_final(舵轮)

### launch 找不到 Gazebo 插件
确认 `rm_control`、`rm_description_for_task` 两个子模块已初始化,并且加入子模块后**重新构建过**工作区。

### 机器人在 Gazebo 里抽搐 / 起步暴冲
1. 用 `rqt_reconfigure` 把对应轮的 `*_wheel_p` 调小;
2. 检查 `config/chassis_params.yaml` 里的 `acc_linear`(m/s²)是否过小——过小会表现为「加油不走、松手还滑」。

### 车跑不直 / 自转漂移
1. 检查四轮 `offset_*` 舵机零偏是否为 0(Gazebo 中无需补偿);
2. 用 `rqt_plot` 对比四轮 `/debug/*_wheel/target` 与 `actual`:某轮明显掉速 → 增大该轮 P 或检查 `wheel_direction` 符号;
3. 里程计漂移可用 `odom_linear_scale` / `odom_angular_scale` 微调(见控制器 README 参数表)。

### 功率限制日志刷屏
`Power Limit Triggered!` 表示虚拟电容能量不足、力矩被 `k_scale` 缩放。正常规则行为;想深入了解见控制器 README「功率限制」一节。

### `rm_description` 与 `rm_description_for_task`
- `rm_description_for_task` 是**仓库目录名**;
- `rm_description` 是**ROS 包名**(package.xml 里定义);
- launch 里 `$(find rm_description)` 用的是包名,二者不要混用。

## ros1_advanced_ws

### gmapping 启动报 `Timed out waiting for transform`
建图时里程计 TF(`odom → base_link`)还没就绪。按 [SLAM 教程](tutorials/03-SLAM建图.md) 的顺序先起仿真再起 gmapping。

### MoveIt 提示找不到 Panda 模型
`panda_moveit_config` 依赖 apt 的 `ros-noetic-moveit` 全家桶,未安装时按 [环境安装](00-环境安装.md) 第 5 节补装。

### usb_cam 打不开摄像头
1. `ls /dev/video*` 确认设备存在;虚拟机里要把 USB 摄像头直通给虚拟机;
2. 无摄像头时可用虚拟设备测试:`sudo modprobe v4l2loopback`(详见 [视觉教程](tutorials/06-视觉处理.md))。

## 还没解决?

按以下信息提问(群聊 / Issue 均可),把这几样贴出来能省一半时间:

1. `roslaunch` 报错全文(不要只截最后一行);
2. `rostopic list` 与 `rqt_graph` 截图;
3. `rosparam get` 关键参数;
4. 本机 ROS 版本:`rosversion -d`。
